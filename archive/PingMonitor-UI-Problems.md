# PingMonitor UI 问题汇总

## 1. 总体设计一致性问题

- 各页面没有遵循同一套稳定的页面间距规范。
- 顶部页面标题栏与下方内容区域之间的垂直间距在不同页面表现不一致。
- 有些页面标题栏与首个内容组件之间留白过大，形成明显的空洞区域。
- 有些页面在调整后又出现内容贴得过近的问题，说明页面间距没有按照统一的设计系统阶梯稳定执行。
- 页面外层、卡片外层、卡片内部、控件组之间的间距层级不清晰。
- 相同类型的内容容器在不同页面使用了不同的外边距、内边距和上下间距。
- 部分页面存在卡片、工具栏、分段控件和内容区域之间边界不明确的问题。
- 页面内容与顶部标题卡片没有形成统一的左右对齐基线。
- 部分页面仍然存在旧的材质背景、裸露分隔区和新卡片样式混用的问题。
- 各页面的标题、工具栏、筛选器、操作按钮和主要内容没有形成稳定、可预测的视觉层级。

## 2. 导航与侧边栏问题

- 最初的界面出现了两个侧边栏：窄图标栏和二级导航栏同时存在。
- 对于当前 PingMonitor 的一级导航结构，双侧边栏造成视觉重复和空间浪费。
- 图标栏与二级导航栏表达的是同一组页面入口，信息架构上存在重复。
- 侧边栏和右侧内容区的比例需要保持稳定，不能因为导航结构重复而挤压内容区域。
- 侧边栏选中态、页面内容选中态和右侧标题状态之间需要保持明确的一致关系；当前截图中虽然选中态可识别，但整体层级仍显得偏重。
- 侧边栏中的分组标题、导航行、选中背景和底部用户信息之间的垂直节奏需要一致。

## 3. 顶部页面标题栏问题

- 顶部标题栏与各页面内容之间的距离不统一。
- 某些页面标题栏下方出现大块空白，首个控件或首张卡片没有紧跟在合理的内容基线之后。
- 某些页面在压缩间距后又变成标题栏与内容贴得过近，缺少应有的呼吸感。
- 标题栏中的状态指示点、页面标题、监控状态、语言切换、停止按钮和开关之间的横向间距需要统一。
- 标题栏的内容宽度与下方页面内容宽度不总是匹配。
- 设置页面尤其明显：标题栏左右边界与下方设置内容卡片的左右边界没有完全对齐。
- 部分页面的顶部标题栏占据了较大的视觉面积，但下面的内容没有以同等清晰的层级承接。

## 4. 监控页面问题

- “监控中主机”区域最初不是卡片，视觉上像一个直接铺在页面背景上的裸区域。
- “监控中主机”标题、快捷入口和主机卡片之间的层级关系不清楚。
- 快速入口区域与主机监控区域的边界表达不一致。
- 主机监控区域、快速服务入口和主机卡片没有形成统一的卡片化布局。
- 内容区域顶部的标题和操作按钮与下方主机网格之间的间距不稳定。
- 主机卡片本身已经是卡片样式，但外层监控区域缺少对应的容器关系，造成“卡片里面再放卡片”或区域边界不明确的观感。
- 快速入口中的主机名称、服务按钮和服务类型标签排列较密，和下方主机卡片的视觉语言不完全一致。
- 监控页面中不同区域的背景色、边框和分隔线使用不统一。

## 5. 统计页面问题

- 顶部页面标题栏与第一排统计卡片之间的间距过大。
- 第一排卡片没有紧跟页面标题形成连续的内容起点。
- 统计卡片之间虽然存在网格关系，但整个页面顶部的留白破坏了网格节奏。
- 页面标题、质量分卡片、维度拆解卡片之间的视觉层级不够紧凑统一。
- 统计页面的卡片间距、页面边距和标题栏间距没有遵循相同的设计系统节奏。
- 统计卡片内部信息较多，但外部页面留白过大，导致内容密度与空间分配不平衡。

## 6. 路由追踪页面问题

- 顶部标题栏与路由追踪工具栏之间的间距不稳定，曾出现明显过大的空白。
- 输入主机名或 IP 的输入框、MTR 模式开关、开始追踪按钮和 NSLookup 操作被放在同一行后，出现布局错误。
- 输入框的宽度分配不合理，可能被固定宽度或右侧控件挤压。
- 右侧操作控件没有形成清晰的操作分组。
- 输入框和操作按钮之间的空间关系不自然，整体像被强行压缩到一条横向区域。
- 当窗口宽度变化或出现多个操作按钮时，工具栏缺乏稳定的响应式布局规则。
- 路由追踪输入区与页面内容的左右边界没有始终保持一致。
- MTR 模式开关的标签、开关本体和其他操作按钮的间距与高度不统一。
- 开始追踪按钮、NSLookup 按钮和复制按钮的视觉权重与交互状态表达不一致。
- 空状态区域与顶部工具栏之间的空间分配不平衡，页面下方出现较大的空白区域。
- 路由追踪结果区域、地图、状态栏和跳表之间的层级关系需要更明确，但当前截图中主要工具栏本身已经先出现了布局问题。

## 7. 网速页面问题

- 顶部标题栏与接口/进程分段切换器之间的间距不统一。
- 分段切换器下方出现过明显的空白区域，红框标示区域说明首个内容卡片没有按统一基线开始。
- 接口/进程切换器与下方“实时网速监控”卡片之间的垂直间距过大或不稳定。
- 分段切换器的宽度和页面内容卡片的宽度关系不协调。
- 页面首个内容卡片与顶部标题栏之间缺少稳定的 16px 级别页面间距关系。
- 网速卡片内部的实时速度、上传/下载指标和控制栏信息密度较高，但卡片外部留白又不稳定，造成整体节奏不平衡。
- 页面内不同网速卡片之间的垂直间距没有明确遵循统一间距阶梯。
- 接口选择器、刷新周期选择器和实时数据内容的对齐关系需要统一。

## 8. 主机管理页面问题

- 顶部标题栏与“已保存主机 / 预设”分段切换器之间存在过大的空白区域。
- 分段切换器与下方主机管理内容区域之间的间距和页面基线不一致。
- “主机管理”标题和“添加主机”按钮所在区域与下方主机卡片列表之间的层级关系不清晰。
- 主机管理内容区域的外层宽度、顶部切换器宽度和标题栏宽度没有完全遵循同一条左右对齐线。
- 红框区域显示页面在标题栏、分段控制器和主机卡片列表之间存在不必要的垂直空洞。
- 主机卡片本身的卡片边界较明确，但卡片列表外层缺少统一的内容容器节奏。
- 主机卡片中的编辑、删除操作图标与主机信息之间的横向关系偏松散。
- 主机管理页面的分段控件与其他页面的分段控件视觉语言不完全一致。
- 主机列表内容、页面标题、操作按钮和分段控件没有形成清晰的“页面标题 → 页面工具 → 内容列表”层级。

## 9. 服务页面问题

- 顶部标题栏与“服务快捷方式”卡片之间存在明显过大的空白区域。
- 服务快捷方式统计卡片内部的标题、添加按钮和分类筛选按钮没有形成清晰的分组关系。
- “全部 / Web / SSH / 自定义”分类按钮的位置和卡片内部标题之间的垂直节奏不够统一。
- 分类按钮区域在卡片内部占用的空间较大，但没有与上方标题和右侧添加按钮形成良好的横向层级。
- “全部”按钮与其他筛选按钮的视觉权重、边框和间距不够一致。
- 服务统计卡片与下方主机服务卡片之间的间距需要统一，当前页面中存在过松或不稳定的间隔。
- 主机服务卡片之间的内容密度和垂直间距不完全一致。
- 服务卡片内的主机名称、地址、服务数量、添加按钮和服务项目卡片之间的关系不够规整。
- 服务项目卡片中的图标、服务名称、URL、类型标签和打开按钮容易出现横向拥挤或截断。
- 服务页面整体使用了卡片，但顶部统计卡片和下方主机卡片之间的设计系统关系不够统一。

## 10. 日志页面问题

- 日志页面最初与其他页面的视觉风格完全不一致。
- 原始日志页面使用全宽裸 `List`，缺少与其他页面一致的卡片容器、边框和页面内边距。
- 日志工具栏使用材质背景，和应用其他卡片式页面混用，导致视觉语言不统一。
- 日志工具栏与日志列表之间的边界不清楚。
- 日志级别标题曾出现重复显示，例如同时出现两个“日志级别”。
- 日志级别筛选器、全部/调试/信息/警告/错误等选项的排列关系不够清晰。
- 清空和导出操作与筛选器之间的空间分组不够明确。
- 日志列表中的状态点、时间、级别、主机和消息没有稳定的列结构。
- 时间列在不同日志行中的水平位置不一致，导致视觉上的列错位。
- 级别列、主机列和消息列之间的间距不一致。
- 没有主机信息的日志和包含主机信息的日志使用不同的内容高度与排列方式，破坏了行结构。
- 主机名称出现在消息区域上方时，会推动消息内容产生不一致的垂直偏移。
- 同一条日志的时间和消息可能出现上下错位，导致日志难以快速扫描。
- 日志行的高度、上下内边距和分隔线节奏不稳定。
- 日志内容的字体混用了普通 UI 字体和等宽字体，层级关系不够明确。
- 日志时间颜色过浅，在大面积列表中可读性不足。
- 日志级别颜色、状态点和文字之间的对应关系不够稳定。
- 日志消息较长时，缺少明确的内容截断或换行规则。
- 日志页面整体留白、行高和列宽没有形成有秩序的日志阅读网格。
- 日志页面看起来像普通列表，而不是一个结构化的应用日志面板。
- 当前日志页面缺少清晰的表头/列定义感，用户需要通过每一行的相对位置猜测字段含义。

## 11. 设置页面问题

- 设置页下方内容区域的宽度曾经与顶部标题栏不一致。
- 设置卡片左右边界没有和顶部页面标题卡片保持同一条对齐线。
- 设置页左右两侧出现不对称或多余的空白边距，截图中红框明确标示了内容区域与标题区域的宽度差异。
- 设置页面的不同设置卡片虽然整体宽度接近，但页面外层边距和顶部标题边距没有统一。
- 系统、状态栏显示、通知等设置卡片之间的垂直间距需要稳定遵循同一套规范。
- 设置卡片内部的标签、分段选择器、开关和说明文字的左右对齐关系需要一致。
- 设置页面部分控件固定为较窄宽度，右侧留白比例与卡片宽度不匹配。
- 版本信息、说明文字和设置控件的右侧对齐基线不完全一致。
- 设置页顶部标题卡片和第一张系统设置卡片之间的间距曾过大，之后又存在贴近风险，整体节奏没有稳定下来。

## 12. 截图中反复出现的共性问题

- 标题栏、工具栏、分段控件、卡片和列表之间缺少统一的垂直间距体系。
- 页面内容在“过松”和“过紧”之间反复变化，没有稳定遵循设计规范。
- 过大的空白通常出现在顶部标题栏与第一个内容组件之间。
- 过近的问题通常出现在标题栏、工具栏卡片和首个内容卡片连续叠放时。
- 卡片的左右边界、页面内容的最大宽度和标题栏宽度没有始终保持一致。
- 同类控件在不同页面的尺寸、圆角、内边距、选中态和间距不一致。
- 一些区域是完整卡片，一些区域却直接铺在页面背景上，导致页面层级断裂。
- 旧的材质条、裸列表、分隔线区域和新的白色卡片同时存在，视觉上缺少统一的容器规则。
- 页面缺少明确的内容阅读顺序：页面标题、页面级操作、筛选/切换控件、主要内容之间的层级有时不明显。
- 信息密集页面没有通过固定列、明确分组或稳定的网格解决信息排列问题。
- 操作控件在窗口宽度变化时容易发生挤压、错位或过度留白。
- 视觉样式虽然采用了相同的亮蓝强调色和圆角卡片，但布局结构没有完全同步，导致“颜色统一、空间不统一”。
