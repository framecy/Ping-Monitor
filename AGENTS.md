# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project

PingMonitor is a macOS 14+ menu-bar network latency monitor written in SwiftUI 6 / Swift 6, with a WidgetKit extension and a small unit-test target. The Xcode project is **generated by XcodeGen from `project.yml`** — do not edit `PingMonitor.xcodeproj` directly; edit `project.yml` then re-run `xcodegen generate`.

## Build & Run

```bash
# One-shot release build → DMG on Desktop (auto bumps build number)
./build.sh

# Regenerate Xcode project after editing project.yml
xcodegen generate

# Debug build / run from the IDE
open PingMonitor.xcodeproj           # then ⌘R

# Tests (single target: PingMonitorTests, host: PingMonitor)
xcodebuild test -scheme PingMonitor \
    -destination 'platform=macOS' \
    -derivedDataPath ~/Library/Developer/Xcode/DerivedData/PingMonitor

# Run a single test (two test files: QualityEngineTests, NetworkSpeedManagerTests)
xcodebuild test -scheme PingMonitor \
    -destination 'platform=macOS' \
    -only-testing:PingMonitorTests/QualityEngineTests/testQualityDimensionScoresAverage

# Package a Debug build into a local DMG (no version bump, reads from build/)
./package_dmg.sh
```

### Versioning

`scripts/bump_build.sh` is invoked by `build.sh` and as a Release pre-build script (see `project.yml`). It mutates **three** places in lockstep — `PingMonitor/Info.plist`, `PingMonitorWidget/Info.plist`, and the `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` lines in `project.yml`. Flags: `--feature` bumps minor (e.g. `2.1.2-R12 → 2.2.0`), `--bug` bumps the `-Rn` suffix, no flag bumps the build number only. Set `SKIP_VERSION_BUMP=1` to no-op (used when `build.sh` re-invokes `xcodebuild`).

### Code signing

The app is **ad-hoc signed** (`-` identity). `build.sh` re-signs the embedded widget appex *first* with its own entitlements, then re-signs the host app — order matters; reversing it invalidates the embedded extension.

## Architecture

### App shell

`PingMonitorApp.swift` (~2700 lines) is the spine. The `@main App` declares only an empty `Settings` scene; the real UI lives behind `StatusBarController` (NSStatusItem + an `NSWindow` it manages itself), which is created by `AppDelegate.applicationDidFinishLaunching`. Closing the main window hides the Dock icon — there is no normal `WindowGroup`. When editing window/menu/status-bar behavior, work in `StatusBarController`, not in a SwiftUI scene.

`PingMonitorViewModel` (also in `PingMonitorApp.swift`) is the single `@MainActor`-adjacent `ObservableObject` shared by every tab. It owns hosts, presets, per-host `HostStats`/`HostProbeDiagnostic`/`ProbeSample` arrays, and the live `Process`/`DispatchSourceTimer` handles for ping/TCP probes. New tabs/views should take this view-model in via `@ObservedObject` rather than introducing parallel state stores.

### Probe/quality pipeline

The probe pipeline is intentionally split into layered Sendable value types defined near the top of `PingMonitorApp.swift`:

- `ProbeFailureReason` / `ProbeFailureCategory` / `ProbePathKind` / `ProbePathSnapshot` — structured failure + path metadata produced per ping.
- `HostProbeDiagnostic` — latest snapshot per host, surfaced to the UI.
- `ProbeSample` — historical sample written into a bounded ring (`maxProbeSamplesPerHost = 4096`).
- `QualityDimensionScores` / `HostQualitySnapshot` / `GlobalQualitySnapshot` / `NetworkQualityEvent` / `QualityTrendPoint` — derived quality scoring (latency / stability / path / bandwidth / resolution / overlay) computed over `NetworkQualityWindow` buckets.

`PingMonitorViewModel.qualitySnapshot(for:window:)` and `qualityTrend(for:window:)` are the public entry points. Sample writes go through a batched `pendingUpdatesBuffer` (a `LockedArray`) flushed on a Combine timer to keep `@Published` churn low — preserve this batching when adding new probe sources.

### Persistence & widget bridge

`ConfigManager` is the canonical persistence layer: pure-JSON files in `~/Library/Application Support/PingMonitor/` (`hosts.json`, `presets.json`, `stats.json`, `settings.json`). It also provides a `migrateFromUserDefaults` path used on first launch. Prefer adding new persisted state via `ConfigManager.save/load` over reaching for `UserDefaults.standard`.

`WidgetDataManager` writes the widget payload through a deliberate **three-tier fallback** because App Groups require a valid Team ID (which this project ships without):

1. `UserDefaults(suiteName: "group.com.pingmonitor.shared")`
2. Direct file in the widget's sandbox container (`~/Library/Containers/com.pingmonitor.app.widget/Data/Documents/widget_data.json`)
3. Shared `~/Library/Application Support/PingMonitor/widget_data.json`

Neither target is sandboxed: the widget explicitly sets `com.apple.security.app-sandbox: false` in its entitlements (overriding the WidgetKit default), and the host app has no sandbox entitlement either. This is what makes the cross-container write in tier 2 work — don't "fix" this by enabling sandbox without also wiring up real App Groups + a Team ID. Widget syncs are throttled to once per 5 s (`widgetSyncInterval`); preserve this when emitting writes.

### Privileged operations

`PrivilegedManager` runs a **single** `osascript`-prompted root bash loop that reads commands from a FIFO at `/tmp/pingmonitor_priv_fifo`. This is how `TracerouteManager` / MTR / interface tooling avoid prompting for the password on every invocation. Anything that needs root should `PrivilegedManager.shared.run("…")` rather than spawning its own `osascript` — re-invoking `osascript … with administrator privileges` re-prompts.

### Logging

`LogManager` (defined in `PingMonitorApp.swift`) is the only logging channel. Use `LogManager.shared.debug/info/warning/error(_ message:, host:)` — **never `print()`**. The `host:` parameter is optional and scopes the entry to a specific host in the audit log UI.

### Larger feature modules

Each tab is its own file driven by the same `PingMonitorViewModel`:

- `MainView.swift` — sidebar router (`SidebarItem` enum) and `MonitorTab`.
- `SidebarView.swift` — the `SidebarView` component rendered inside the split view.
- `DashboardView.swift`, `HostDetailView.swift`, `EditableHostCard.swift` — statistics + host detail + cards.
- `NetworkSpeedManager.swift` / `NetworkSpeedTab.swift` — interface + per-process speed sampling.
- `TracerouteManager.swift` / `TracerouteView.swift` — traceroute/MTR + map visualization (uses `PrivilegedManager`).
- `TailscaleManager.swift` / `TailscaleTab.swift` — `tailscale` CLI integration, exit-node switching.
- `ServicesTab.swift` — per-host SSH/Web shortcuts; SSH auth uses an `expect` script to bypass AppleScript-only auth.
- `KeepAliveManager.swift` — adaptive idle detection on `utun*` interfaces; emits `.keepAliveStatusChanged` notifications consumed by the ping loop.
- `FolderMonitor.swift` — `DispatchSourceFileSystemObject` wrapper that debounces filesystem changes; used to watch the config directory.
- `Localization.swift` (`LanguageManager.shared.t(...)`) — runtime zh/en switch; UI must observe `languageManager.currentLanguage` and re-render rather than reading bundle strings.
- `Theme.swift` / `Components.swift` — design tokens (`Theme.Colors.*`) and shared UI primitives like `ModernCard`.

### Concurrency notes

The codebase is on Swift 6 strict concurrency. `PingMonitorViewModel` mutations are expected on the main actor; probe results are produced on background queues and routed through the batched buffer. `LockedArray` and the small `Box` types (`ProbeResolutionBox`, `ProbeFailureBox`) at the top of `PingMonitorApp.swift` exist specifically to satisfy `@unchecked Sendable` for cross-actor handoff — follow that pattern instead of weakening actor isolation when adding similar state.

One subtlety that bit us on macOS 26 (Tahoe): a `DispatchSource` timer (or any background dispatch callback) that captures an `@MainActor`-isolated `self` gets a Swift 6 executor-isolation prologue at the closure entry. On the stricter Tahoe runtime this prologue runs `_swift_task_checkIsolatedSwift → _dispatch_assert_queue_fail → SIGTRAP` the moment the callback fires on a non-main queue. Both probe paths therefore avoid that shape: ICMP keeps `readabilityHandler` → `Task.detached` → the `nonisolated` `parsePingLine`; TCP drives its timer on `DispatchQueue.main` and is pure-callback (no `Task`/`await`) — `measureTCPConnectLatency(... completion:)` runs its `NWConnection` I/O on a private serial queue and the completion only writes the `LockedArray` off-actor. When adding a new probe source that captures `self` in a dispatch callback, prefer either a main-queue timer + callback (TCP) or a `Task.detached` wrapping a single `nonisolated` method (ICMP) — never capture an `@MainActor` `self` inside a background dispatch closure that then drives it synchronously or via `await` on a nonisolated `async` member.

### Window lifecycle

The app is `LSUIElement` (a pure menu-bar, no Dock icon). `StatusBarController` owns `mainWindow` (`isReleasedWhenClosed = false`) and toggles it via the status-item click → `toggleWindow` → `showWindow` / `orderOut`. Closing the window must never let it reach the real NSWindow close path: `windowShouldClose(_:)` intercepts it, calls `orderOut(nil)`, flips to `.accessory`, and returns `false`, so the window only hides (stays fully alive) and `toggleWindow`'s `isVisible` branching stays symmetric. `showWindow()` switches to `.regular` first, then `makeKeyAndOrderFront` + `NSApp.activate()` (no-arg, modern semantics, macOS 14+) + `orderFrontRegardless()` as a hard front fallback — `ignoringOtherApps:` no longer reliably raises an agent app's window above the frontmost app on Tahoe. Preserve this show/hide symmetry and the `.regular`→activate→front ordering when touching the status-bar window.

## 设计规范（UI 必读）

设计系统分三层：**令牌**（`Theme.swift`）→ **组件**（`DesignSystem.swift` / `Components.swift`）→ **规则**。改任何 UI 前先读本节；拿不准就先看相邻同类代码怎么写。

### 令牌即法律

- 间距只能用 `Theme.Space`：阶梯 `xxs2 / xs4 / sm8 / md12 / lg16 / xl20 / xxl24`（稀疏档 `xxxl32 / huge40` 仅限空态类大留白）。页面语义别名优先于裸档位：`pagePadding / pageTopGap / cardGap / tileGap / controlGap / sectionGap`
- 禁止：padding/spacing 数字字面量、负 padding 补齐、裸 `.padding()`、给 segmented Picker 定宽却不给 `.controlSize(.small)`
- 字体只能用 `Theme.Fonts.ui / .number / .icon`，禁止 `.font(.headline)` 这类系统字体逃逸；数值/时间戳/主机名一律 `.number()`（等宽保证纵向对齐）
- 圆角与颜色只出自 `Theme.Radius` / `Theme.Colors`

### 页面骨架

- 标准滚动页 MUST 用 `ScrollPage { }`（可选 `toolbar:` 槽），工具行用 `ToolbarRow`
- 非标准结构（Traceroute 的 VSplitView、Logs 整页单卡、进程列表自管滚动）不硬套 ScrollPage，但留白必须引用同一批 Space 常量

### 组件对照表（有现成组件时禁止手造）

| 需求 | 用 |
|---|---|
| 卡片容器 | `.card(padding:background:)`（`ModernCard` 是兼容薄封装） |
| 可悬浮网格瓦片 | `.hoverLift(isHovered:accent:)` |
| 页级分段切换 | `SegmentedSwitcher`（滑块动画内置） |
| 可点筛选 chip | `FilterChip` |
| 标签+数值指标块 | `StatTile(.plain / .tinted)` |
| 徽标 | `Badge(.tinted / .pill)` |
| 设置行（左标签右控件） | `SettingsRow(label:description:controlWidth:control:)` |
| 表格列宽 | 表头与行共用常量对象（仿 `LogColumnWidths` / `HopColumnWidths`） |

### 已知例外（写代码时可依赖）

- Widget 目标不引用 Theme（历史现状）；新增 Widget 界面先本地定义值并注释
- `EditableHostCard` 不用 hoverLift：它的边框/悬停光晕携带主机状态色，是信息不是装饰
- 存量偏离阶梯的光学微调值（3/5/6/7/10/14/30pt 等，见审计基线 ~144 处）集中在卡片内部小组件：改到哪个组件就顺带归阶，不做专门批量替换

### 审计

`scripts/design-audit.sh` 报告四类违规计数（默认 report-only 恒退出 0；`--strict` 有违规才退 1）。UI 改动提交前跑一次：**新增违规必须清零，存量计数只许降不许升。**
